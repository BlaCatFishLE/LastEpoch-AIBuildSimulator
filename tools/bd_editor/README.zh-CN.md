# BD 配置工作台（计算接入 v1）

本机应用。完整日常流程见 `docs/workflow.md`：导入基础 BD → 调整配置 → 应用条件 → 计算/比较 → 按需研究 → 保存与交付。

## 启动与导入

在仓库根目录运行 `scripts/le.ps1 editor --port 8766`，打开 `http://127.0.0.1:8766/`。也可用项目 Python 执行 `tools/bd_editor/service.py --port 8766`。不需要安装前端依赖；只读 dataset 和 affix-db 必须可用。`--tool-home` 是兼容参数，编辑器名称统一使用数据库英文原文。

“导入配置”支持项目已有 BuildSpec `build.json` 或编辑器导出 JSON；导入为独立配置并保留来源身份。原始离线存档先经过正式 import 流程转换，编辑器不直接读取游戏存档。空构筑可用“新建 BD”。

## 配置和保存

1. 保留基础配置，复制不同尝试并命名，选择比较基准。
2. 在装备、完整被动、当前职业技能节点、神像和祝福页调整。
3. 已装备物品修改阶级、roll 或词缀后自动应用并保存；拖条右侧显示后端规则恢复的实际属性值，下方为进度/raw roll。新候选物品需点击“应用候选物品”。
4. 切换、计算、保存版本与导出前等待当前修改完成。失败显示“未保存”并保留输入；“立即保存修改”可显式提交。
5. “保存版本”保留恢复点，“导出配置”保留完整构筑和编辑条件。删除配置进入回收站，可恢复，不删除原始构筑/历史报告；旧窗口不能复活已删除配置。

配置检查与计算覆盖分别显示。基底、等级、前后缀数量、相同 affix ID 重复、阶级和 roll 继续检查；`category_group` 只作分类，不是互斥组。特殊获取路径、职业额外限制和神像解锁格位等未完全确认处保留提示。预算自动计入可解析的来源，不以源技能等级或已用点数伪造预算。

## 条件与计算

在“条件与 Buff”选择用户确认的主技能，设置目标、观察时间、策略与 Buff 并应用，再点右侧“计算当前配置”。条件随配置独立保存，复制/导出/恢复保留；同装备也能比较不同条件方案。

来源覆盖当前被动、全部专精及已映射装备。失效来源的旧状态保留供恢复/研究，不伪装有效 Buff。只读条件按目标派生；下一次施法效果与持续循环分别处理。

计算等待草稿保存，冻结当前 BuildSpec/场景，按稳定 ID 查询共享知识，再调用统一编译、执行、结果校验和报告阶段：

| 路径 | 当前行为 |
|---|---|
| A | 构筑、调度、非运行时设置与依赖相同，复用成功计划，对支持的运行时条件重算 |
| B | 装备/词缀/节点、策略、窗口等变化，按当前基底恢复实际值并重新绑定、编译 |
| C | 缺定义、未映射条件或不支持能力，保存研究任务并给出复制/下载入口 |

目前需要把研究任务交接到对话，按钮不会启动后台 agent；部分覆盖的成功结果也能交接未覆盖项。Throne of Ambition 已绑定固定 0–20 层 Fire/Cold 增伤并去重；不模拟叠层获取/维持，点燃继承仍保留假设。

第一版七系目标抗性必须相同；策略、窗口与机制按当前能力检查。计算成功不等于完整游戏合法性、全职业覆盖或完整战斗模拟。配置变化标为待更新；失败保留上次成功结果，旧请求不能覆盖新配置。

## 详情与比较

完整详情沿用共享玩家报告，展示总览、组件和乘区、实际来源、时间/循环、全部装备词条/神像/祝福、角色、已投入被动和专精节点、计算时全部条件。报告是求值快照，只读；返回编辑器调整后生成新结果，旧报告不覆盖。

比较默认按各自条件显示 DPS、窗口总伤害、次数和并发差异，并保留目标/Buff 差异。技能、窗口或覆盖范围不同则不排名；统一条件模式尚未实现。保存配置和保存结果不能混为一项。

## 数据和维护

- `data/editor-workspace/<config-id>/current.json`：本机草稿。
- `revisions/`：保存版本；`evaluations/<evaluation-id>/`：冻结配置、实际输入、知识解析、定义/场景、计划、结果、门禁、报告及任务。
- 计划复用保留原冻结引用，`execution-case.json` 记录执行案例；`research-resolutions/` 可保存研究完成记录。
- 原始来源、已发布 BuildSpec revision、dataset 和历史报告不回写。工作区不默认公开提交，Git 排除缺口由交接任务处理。
- 代码或规则更新后重启服务并刷新页面。定义/规则/数据/实现变更使计划复用失效；语言与配置名称不改变数值身份。

维护前按 `docs/contracts/bd-editor-player-projection.md` 核对英文名称、说明过滤、技能等级作用域、预算、槽位、保存与分类字段。计算设计见 `docs/design/bd-editor-calculation-integration.zh-CN.md`；主流程与研究闭合见 `docs/workflow.md`。

## 现有定向检查

| 文件 | 范围 |
|---|---|
| `tests/test_service.py` | 配置持久化、隔离和基础输入校验 |
| `tests/test_player_regressions.py` | 玩家名称/说明、槽位和预算边界 |
| `tests/test_conditions_and_delete.py` | 条件保留、删除/恢复与版本冲突 |
| `tests/test_calculation.py` | 当前输入 A/B/C、执行绑定和过期结果隔离 |
| `tests/test_item_editing.py` | 阶级/roll/实际值的保存读取一致 |
| `tests/test_affix_categories.py` | 同分类可共存与真实重复/数量限制 |

这是按变更选取的检查索引，不是每次全跑清单。部分真实链检查依赖当前本机输入；缺少时不能把 skip 称为端到端通过。文档整理不重复计算或网页验证；交互变更默认仅一条相关成功路径。
