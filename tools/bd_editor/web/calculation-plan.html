一套计算引擎，三种准备路径

根据知识覆盖与输入变化分流。换得多不一定需要研究，只改一个节点也可能引入新机制。

路径 A · 即时重算

只改已支持条件

构筑与规则绑定一致，目标 / Buff 属于当前接口支持的运行时字段。

复用当前重算服务 → 执行 → 生成新结果与详情。

路径 B · 重新绑定后计算

改动构筑，规则已齐全

更换装备、词缀数值或已有节点后，全部效果仍能绑定现有规则。

导出当前输入 → 重新绑定 → 编译计划 → 执行与生成详情。

路径 C · agent 研究

发现计算缺口

未知暗金、未支持触发、转换或新的召唤 / 调度机制影响声明范围。

知识检索 → 研究缺口 → 最小验证 → 知识沉淀 → 回到统一计算链。

路径 A · 即时重算

先检查运行时能力、来源与绑定；通过后复用已有重算接口。

编辑器中的计算入口

计算结果

对应最后一次成功计算
  • 一个主要操作：“计算当前配置”。先保存当前输入并自动选择准备路径。
  • 发现缺口时显示“需要研究”的具体原因，提供“研究并计算”。agent 不因普通改动自动反复启动。
  • 成功后显示对应主技能、观察窗口、目标与预计 DPS；可点击“查看计算详情”。
  • 继续编辑后显示“结果待更新”，保留旧结果并标注其对应版本。

点击“查看计算详情”之后

打开独立、可分享的本机报告。详情固定到一次计算，查看时不会被后续编辑改写。

总览与计算条件

主技能、输出范围、目标、Buff、操作策略、观察窗口及结果版本。

完整构筑配置

装备、全部词条、神像、祝福、被动与专精节点，保留未参与伤害的属性。

伤害构成与各乘区

每个组件的基础 / 附加伤害、加算、独立增伤、适用暴击和目标结算；展开真实来源。

时间与循环、来源与 Buff

有真实执行数据时展示频率、持续、命中 / 施加和时间记录；区分常驻、临时、仅下一次施法。

比较与结果一致性

  • “各自条件”比较保留两个 BD 的 Buff 与目标差异；“统一条件”比较只统一双方实际支持的公共场景。
  • 一个结果绑定构筑、条件、数据库、规则和引擎版本。旧请求不能覆盖新配置结果。
  • 未知来源不当作零收益；不完整结果标明可用范围。已知错误进入修复，不能伪装成可用结果。
  • 沿用现有统一报告与重算渲染入口，前端不再维护另一套 DPS 公式。

建议实施顺序

  1. 条件映射、输入指纹、能力预检与结果记录。
  2. 接通路径 A 和详细报告入口。
  3. 接通路径 B 的重新绑定 / 编译 / 计算。
  4. 建立研究任务交接，接通 agent 研究与知识收尾，再回到同一计算链。
