# BD 编辑平台：玩家投影与预算修正规则

适用范围：编辑平台与共享物品可读层。以下规则用于日常接入/编辑，不扩大默认网页验证范围。

1. **游戏名称默认使用英文原文。** 玩家界面的按钮和说明保留中文；物品、词缀、职业、专精、技能和节点按当前数据库实体 ID 解析英文名称。比较时依赖稳定 ID 和实际数值，不能把导入记录里的中文标签与英文标签视作不同词缀。旧配置不要求重新导入。
2. **原始证据与玩家文本分开。** `effects.raw_text` 可能是 JSON 对象序列化内容；不能直接加入节点说明。玩家投影过滤对象/数组元数据，只展示说明和效果名；游戏标记如 `'{‘Haste’}'` 应还原为可读名称，原始字段保持保留。前置关系通过节点名称和所需点数表达。
3. **先判定属性命名空间，再解析 tags。** property 88（Level of Skills）中，specialTag=1 时 tags 是技能索引，必须映射具体技能；不得按伤害位掩码展开。例如 index 15 指向 Black Hole。specialTag=2..6 限定职业；7..11 限定属性缩放；0 才按普通标签作用域处理。共享入口为 `Catalog.skill_level_scope`，显示与预算共用。
4. **基础技能等级与可用点数不是同一字段。** 预算从当前装备、实际 roll 与当前技能/节点重新计算；不能把 `source_level=20` 直接当总预算，也不能从 `points_total` 反推预算来消除错误。Black Hole 的 Red Giant、Binary System 标签规则来自版本化规则文件；未解析的转换显示范围或待核实。换装、改节点、恢复版本后同样重算。用户手动覆盖须明确标注，留空使用自动预算。
5. **槽位先规范化。** 当前构筑协议的腰带槽是 `waist`，数据库装备类型为 `belt`。界面、比较、编辑、缺席槽位摘要统一使用 `waist`；旧编辑器 `belt` 别名仅在规范化边界处理，不丢弃物品实例或词缀。
6. **专精技能仅展示当前职业。** 列表依据 `trees.class_entity_id` 与当前职业身份过滤；导入时保留已有未知字段，不用隐藏其他职业来静默删除来源数据。

本次定向证据：`black-hole-beta33-native-20261111` 与 `black-hole-beta33-v4-20261112` 的腰带均为 Noble Sash；遗物显示 `T8 · +6 to Black Hole`。Black Hole 已投入 36 点，按当前已解析装备与火/冰双星节点可用 37 点；移除遗物后可用 31 点，仍应报告真实超额。

必要检查：名称仅语言不同不产生词缀差异；玩家节点文本不含对象元数据；特定技能/职业等级作用域不串扰；保留腰带及全部词缀；完整预算正例与移除加成的负例。函数/API 层检查后，网页仅验证一条相关路径，不启动历史 DPS 重算或全仓回归。

证据为数据库与参考规划器语义推导，不代表新增游戏内实测。自动预算当前只覆盖可解析的装备技能等级修饰；其他来源与动态作用域不能静默当作零或伪装完整支持。


## 装备编辑的保存与当前值（2026-11-13）

- 已装备物品的词缀阶级、roll、固有/暗金取值和词缀调整自动应用并写入草稿。切换装备、页签、配置以及保存版本、导出、计算前，须等待当前物品的校验、应用和保存完成；不能只保存尚未包含候选修改的旧 BuildSpec。替换为另一件候选装备仍需要显式应用。
- 编辑会话绑定配置 ID 与具体槽位/实例，异步响应绑定修改序号；旧响应不覆盖新拖动值。失败保留输入并显示“未保存”，不以绿色已保存提示或切页丢弃修改。卸下物品须结束原编辑会话，不能被迟到的保存重新装备。
- 阶级、raw roll 和解码后的实际属性值须一同持久化。编辑输入与已应用物品不得共享可变数组/词缀对象；创建与载入草稿均复制输入，避免改变表单却保留旧显示值。
- 拖条旁显示实际属性值与单位；进度/raw roll 作为次级信息。由 `Workspace.preview_item` 复用 `le_build.rolls` 为当前基底、阶级和属性生成精确取值表，浏览器只读取，不另写插值或舍入算法。复合词缀保留各属性值；切换阶级/来源后使旧取值表失效。
- 修复缺失槽位时先核对同一构筑的来源 BuildSpec 与已保存版本；只按用户指定恢复该槽位，修复前后保存版本并记录来源，其它配置保持。不能在每次读取时自动填回有意卸下的装备。

本次检查：`tools/bd_editor/tests/test_item_editing.py` 覆盖阶级/roll/实际值保存读取一致、端点值和越界拒绝；隔离网页中修改 Apex of Thought 的 Fire Resistance 为 T6/roll 0，切到胸甲再返回，仍为 T6/+50%，并确认草稿自动保存。只验证这一条相关路径，未运行历史伤害案例或全仓回归。


## 分类字段不能用于互斥校验（2026-11-13）

`affix-db.affixes.group_id` 是宽泛的词缀分类标记，不能据此拒绝同一物品上的其它词缀；编号相同不是“同一词缀”或“互斥配方”的证据。当前真实构筑中，持续伤害与火焰/召唤物火焰穿透同为分类 2，元素持续伤害与火焰伤害也可同为分类 2；元素抗性与火焰抗性同为分类 0。编辑器候选接口将其命名为 `category_group`，避免再当作排他组使用。

相同 affix ID 重复、前后缀数量上限、基底适用性、阶级、roll 类型/范围及特殊通道限制继续检查。若要增加真正互斥校验，必须绑定明确的规则/稳定 ID，不按分类、名称或属性近似推断。已有装备的纯 roll 修改仍须通过这些真实边界，不能只跳过所有合法性检查。

定向回归：`tools/bd_editor/tests/test_affix_categories.py` 验证四条同分类可共存词缀的取值修改与保存读取，并以重复同一 ID、超过前缀数量作反例。网页仅在独立主手副本验证一次 roll 修改成功，用户原始取值不改动。此变更修正字段使用与校验，不新增伤害或游戏机制规则。
